What happens to one tool call


The same five steps, every time, for every tool.


    

  1. Agent proposes
    A tool name and arguments. Nothing runs yet.
    2. 

  2. Gate cleans it up
    Paths and strings are decoded and checked first, so the policy judges what would really run.
    3. 

  3. Policy decides
    Allow, hold for approval, or deny. Anything no rule matches is denied.
    4. 

  4. A person approves
    For held calls: a different person, for that exact call, before it expires.
    5. 

  5. It runs once, and is sealed
    Policy is checked again at the moment of execution. Every step goes into the log.
    6.

Three promises you can check
Each one is a test in the repo, not a sentence in a brochure.




The policy sees what will actually run
An encoded or sneaky path is decoded or refused before any rule is applied, so a disguised request cannot slip past a rule that only looks at plain text.


An approval is for one exact call
Your yes is tied to a hash of that call. Change a single character and the approval no longer applies, and the person who approves cannot be the agent's own requester.


History cannot be edited quietly
Each record includes the hash of the one before it. Change, delete or reorder a record and verification fails at the exact spot. Try it below.

Why not just tell the agent to behave?


Instructions in a prompt are advice. A gate is enforcement outside the model.


Rules written in the promptAgentGate


Who enforces itThe model, which can be talked out of itCode outside the model, which cannot


Unlisted actionsWhatever the model decidesDenied by default


Risky actionsMaybe asks, maybe does notHeld until a different person approves that exact call


Proof afterwardsChat transcriptHash-chained log that shows edits
